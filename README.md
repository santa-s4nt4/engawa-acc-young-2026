# engawa-acc-young-2026

御朱印帳の表紙写真を撮ると、登録済みの帳面と照合してその帳面のページ(集めた印の一覧)を開くデモアプリ。サーバーやビルド工程を持たない静的サイトで、GitHub Pagesでの公開を想定している。

## ページ構成

3つの役割に完全に分離している。ページ間はJSファイルもCSSファイルも共有しない(共通部分だけ `js/common.js` 等にまとめている)。

| ファイル | 役割 | 想定する使われ方 |
|---|---|---|
| [index.html](index.html) | **読み取り** | 一般公開の入口。表紙を撮影 → 登録済み帳面と照合 → 一致したら [note.html](note.html) の該当ページへ遷移する。それ以外のページへのボタン遷移は用意していない。 |
| [note.html](note.html) | **帳面** | 帳面の一覧、および個別の帳面ページ(集めた印の表示、進捗バー)。JSONの書き出し/読み込みもここにある。 |
| [reg.html](reg.html) | **登録**(隠しツール) | 帳面を新規登録・編集するための管理用フォーム。index.html/note.htmlのどこからもリンクされておらず、URLを直接開いたときだけ使う。 |

`reg.html` は `?id=<帳面ID>` を付けると既存の帳面を編集できる。IDは `note.html` の帳面ページ下部にヒントとして表示されている。

## データの流れ(GitHub Pages公開を前提とした設計)

GitHub Pagesは静的ホスティングでサーバー側の書き込みができないため、「登録はローカルで行い、その結果をリポジトリにコミットして公開する」という運用にしている。

1. 手元のPCで `reg.html` を開き、表紙の写真と帳面の中身(節・スタンプ一覧)を登録する。保存内容はそのブラウザの **localStorage**(キー `goshuin:books:v1`)にのみ残る。
2. `note.html` の「書き出す(ダウンロード)」で、登録済み全帳面を1つのJSONとしてダウンロードする。
3. ダウンロードしたJSONで [data/books.json](data/books.json) を上書きし、コミット・pushする。

読み込みの優先順位は [js/common.js](js/common.js) の `store.load()` に実装されている。

1. `window.storage`(ホスト環境がこのAPIを提供する場合)
2. `localStorage`(reg.htmlで登録した下書き。手元での確認用)
3. `data/books.json`(上記どちらにもデータが無ければフォールバック)

これにより、`reg.html` を一度も触っていない訪問者のブラウザ(=GitHub Pagesの一般来場者)では自動的に `data/books.json` がfetchされ、pushされた内容がそのまま読み取り〜帳面遷移に反映される。逆に手元のブラウザでは、localStorageの内容が優先されるため「登録 → note.htmlで確認 → 問題なければ書き出してpush」という一連の作業がそのまま行える。

`data/books.json` の中には帳面ごとに `id / name / subtitle / accent / intro / sections` と、写真から計算した特徴ベクトル `samples[].embedding`、224px正方JPEGとして埋め込まれた `samples[].thumb` が入っている。**note.htmlの帳面ページはこのJSONの中身だけから生成されており、サーバー側の処理は一切ない。**

## 照合の仕組み

- 表紙写真はキャンバスに224px正方(中央切り出し)で描画し、画像特徴ベクトルに変換する。
- 登録済み全帳面の全サンプル写真とコサイン類似度を計算し、最も高いものを1位候補とする。
- 「1位の類似度が閾値以上」かつ「1位と2位の差が一定以上」の両方を満たしたときだけ一致と判定し、該当の帳面ページへ遷移する(`index.html` の「採用の閾値」「1位と2位の差の下限」のスライダーで調整可能)。「一致したら自動でページを開く」がオンなら0.7秒後に自動遷移する。

## 特徴抽出エンジン([js/engine.js](js/engine.js))

- 既定では **MobileNet v2**(TensorFlow.js、CDN経由)を画像特徴抽出に使う。CDNからの読み込みに失敗した場合は、色相・輝度・エッジのヒストグラムを組み合わせた**内蔵の軽量特徴量**に自動フォールバックする。
- MobileNetの読み込みは画面表示をブロックしない。ページを開いた瞬間は内蔵の軽量特徴量で操作可能にしておき、裏側でMobileNetを読み込む。読み込み中は画面上部にゲージ(`#loadbar`)を表示し、完了すると自動的に消える。
- 撮影・登録の直前に、その時点で有効なエンジンと異なるエンジンで作られたベクトルがあれば自動的に再計算する(`reembedStale()`)。エンジンの種類が混在したまま比較されることはない。
- `note.html` は特徴抽出を行わないため `engine.js` を読み込んでいない。

## ファイル一覧

```
index.html   読み取り画面
reg.html     登録画面(隠しツール、URL直打ち専用)
note.html    帳面(一覧 + 個別ページ)
data/
  books.json     公開用の帳面データ(reg.htmlで書き出したJSONで上書きする)
css/
  common.css     3ページ共通(レイアウト・ボタン・フォーム等)
  index.css      読み取り画面専用(類似度ランキング・判定・スライダー)
  reg.css        登録画面専用(色スウォッチ・節エディタ)
  note.css       帳面専用(一覧カード・帳面ページ・JSON書き出しダイアログ)
js/
  common.js      保存層(store)と基本ユーティリティ($, esc, uid)。3ページ共通
  engine.js      特徴抽出(MobileNet / 内蔵簡易特徴量)。index.html・reg.htmlのみ
  index.js       読み取り画面のロジック
  reg.js         登録画面のロジック
  note.js        帳面(一覧・個別ページ)のロジック
```

## ローカルでの動作確認

`fetch('data/books.json')` は `file://` で直接HTMLを開くとCORS制限で動かないため、簡易サーバーを立てて確認する。

```sh
python3 -m http.server 8000
# http://localhost:8000/index.html を開く
```
